# 레거시 ERP에서 옮기는 순서

[추측] 첫 단계는 읽기 전용 연결이다. 데이터 이관과 외부 전송은 이 설계 문서의 승인만으로 실행하지 않는다. 각 단계의 실제 연결·기록·전환은 담당자의 별도 승인을 받은 작업으로 진행한다.

[추측] 착수 전에 MIT 구성의 채택 가능성을 확인한다. Enterprise 제외가 검증되지 않으면 운영 설치를 보류한다. The_IM 외부 연결의 허용 여부도 먼저 결정한다.

## 단계별 계획

| 단계 | 옮기거나 확인할 업무 | 원본과 허용 동작 | 통과 조건 | 실패하면 |
| --- | --- | --- | --- | --- |
| 1. 읽기 전용 연결 | [추측] 거래처·상품·단가·재고·주문의 표본 조회 | [추측] 레거시 ERP가 원본이다. 변경 권한 없는 연결만 사용한다. 자료 저장도 승인된 범위로 제한한다. | [추측] 조회 범위·코드·기준 시각을 대조한다. 쓰기 요청이 실제로 거절되는지 시험 환경에서 확인한다. | [추측] 조회를 중단한다. 운영 자료를 수정하지 않는다. |
| 2. 코드와 거래처 | [추측] 코드 대응표, 회사·담당자, 상품 목록 | [추측] 레거시가 원본이다. 승인된 표본만 별도 시험 저장소에 복사한다. | [추측] 중복 코드와 누락을 사람이 해결한다. 다른 회사 자료의 조회를 차단한다. | [추측] 시험 복사본 사용을 멈춘다. 운영 코드에는 쓰지 않는다. |
| 3. 단가와 견적 비교 | [추측] 가격표, 수량 환산, 필요하면 견적 | [추측] 레거시가 원본이다. 새 시스템은 같은 입력의 계산 결과만 비교한다. | [추측] 대표 계약·수량·날짜·통화의 결과를 대조한다. 차이 원인을 모두 설명한다. | [추측] 새 단가를 운영에 적용하지 않는다. |
| 4. 발주 제안·사람 승인 | [추측] 구매 추천과 승인 절차 | [추측] 구매발주는 레거시에만 확정 기록한다. 사람의 접수 승인 후 제안을 저장한다. 사람의 실행 승인 후 기존 업무로 발주한다. | [추측] 무승인·오래된 제안·중복 요청을 막는다. 실제 발주 번호와 승인한 내용을 대조한다. | [추측] 새 실행기를 멈춘다. 기존 사람 절차를 사용한다. |
| 5. 구매·입고 이관 | [추측] 공급사 발주, 입고 예정, 검수 | [추측] 선택한 공급사·기간부터 우리 구매 모듈을 원본으로 바꾼다. 실재고는 아직 레거시가 원본이다. | [추측] 미완료 발주와 부분 입고를 대조한다. 레거시의 중복 발주 입력을 막는다. | [추측] 새 쓰기를 멈추고 미완료 건을 사람이 대조한다. |
| 6. 실재고 이관 | [추측] 창고별 현재 재고·예약·필수 로트 | [추측] 선택한 창고의 재고 원본을 Medusa로 바꾼다. 입고·출고 수량 반영도 함께 전환한다. | [추측] 기준 시각 재고와 열린 예약을 대조한다. 창고 이동·반품·입고 경계를 시험한다. | [추측] 자동 쓰기를 멈춘다. 차이를 확인한 후 원본 복귀 여부를 사람이 승인한다. |
| 7. 판매·반품 이관 | [추측] 판매주문, 출고, 주문 수정, 고객 반품 | [추측] 선택한 거래처부터 Medusa를 원본으로 바꾼다. 재고가 이미 이관된 주문만 대상으로 한다. | [추측] 열린 주문·예약·출고·반품을 대조한다. 수정과 재시도가 수량을 중복 반영하지 않는지 확인한다. | [추측] 신규 주문 유입을 멈추고 진행 중 건을 대조한다. |
| 8. 예측 고도화 | [추측] 부족 예측과 발주량 추천 | [추측] 확정 판매·입고 이력만 읽는다. 추천은 원본 자료가 아니다. | [추측] 과거 기간을 나눠 단순 평균 추천과 비교한다. 담당자가 허용 오차를 정한다. | [추측] 예측 추천만 끈다. 사람 발주 절차를 유지한다. |

## 전환 절차

[추측] 다음 절차를 업무별로 반복한다. 전사 자료를 한 번에 전환하지 않는다.

1. [추측] 담당자가 대상 거래처·창고·기간과 전환 시각을 승인한다.
2. [추측] 해당 업무의 변경을 잠시 멈춘다. 기준 자료와 미완료 업무를 확보한다.
3. [추측] 승인된 범위의 자료를 복사한다. 코드·건수·수량·통화별 금액을 대조한다.
4. [추측] 읽기 화면, 사람 승인, 중복 요청, 장애 복구를 합성 데이터로 확인한다.
5. [추측] 담당자가 원본 전환을 승인한다. 이전 시스템의 해당 쓰기를 막는다.
6. [추측] 전환 뒤 새로 생긴 자료까지 다시 대조한다. 차이가 남으면 자동 처리를 멈춘다.

## 중복 기록과 복구

[추측] 외부 업무 번호와 내부 ID의 대응표를 보존한다. 같은 원본 자료를 다시 읽어도 새 거래처·상품·주문을 만들지 않는다. 오래된 자료가 새 값을 덮어쓰지 않도록 기준 시각과 버전을 비교한다. 외부 시스템에 버전이 없으면 허용 가능한 대조 방법을 정할 때까지 자동 쓰기를 보류한다.

[추측] 원본 복귀는 백업을 바로 덮어쓰는 작업이 아니다. 전환 후 발생한 새 업무를 먼저 대조한다. 실제 실행 여부가 불명확한 발주·출고는 원본에서 조회한다. 취소나 정정도 새 사람 승인을 받는다. 회계 자료 이관과 전자세금계산서 이관은 이 순서에 포함하지 않는다.
