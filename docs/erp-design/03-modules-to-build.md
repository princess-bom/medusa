# 직접 만들 모듈과 예상 크기

[추측] 아래 크기는 구현 기간이 아닌 상대 비교이다. S는 기존 자료를 읽는 좁은 기능이다. M은 새 자료와 업무 규칙을 가진 기능이다. L은 여러 시스템의 승인·수량·실행을 함께 맞추는 기능이다. 위험도는 잘못 처리했을 때의 업무 영향과 미확인 정도를 뜻한다.

## 개발 후보

| 모듈 | 크기 | 위험도 | 만들 내용과 이유 |
| --- | --- | --- | --- |
| 조회·코드 대응 화면 | S | 중간 | [추측] 상품·거래처·창고 코드를 비교한다. 중복 코드를 사람이 고르게 한다. 자동 병합은 하지 않는다. |
| 레거시 ERP 어댑터 | L | 높음 | [추측] 처음에는 조회만 한다. 이후 승인된 쓰기, 외부 번호 대응, 중복 방지, 결과 재조회를 담당한다. 실제 API를 아직 모른다. |
| B2B 거래처 | M | 높음 | [추측] 회사·담당자·납품처·접근 범위를 관리한다. 고객그룹만으로 회사 권한을 대신하지 않는다. |
| 도매 단가 | M | 높음 | [추측] 거래처·상품·수량·기간별 계약을 관리한다. 가격표를 재사용하되 박스 환산과 우선순위를 명시한다. |
| 견적 | M | 중간 | [추측] 견적 버전·유효기간·고객 수락을 관리한다. 사내 발주 승인과 분리한다. 첫 이관에 필요한지는 eddy가 결정한다. |
| 공급사·구매발주 승인 | L | 높음 | [추측] 공급사, 발주 품목·납기, 변경안, 사람 결정을 연결한다. 승인 전 발주서 기록·전송을 막는다. |
| 입고·검수 연결 | M | 높음 | [추측] 발주 수량, 실입고, 파손·부족 수량을 비교한다. 사람 승인 후 재고에 반영한다. 입고 예정은 가용 재고로 세지 않는다. |
| 로트·유효기간·창고 이동 | L | 높음 | [추측] 필요하면 로트별 잔량과 이동 출고·도착을 관리한다. 대상 업무가 필수이면 재고 이관 전에 구현한다. |
| 재고 예측 | M | 높음 | [추측] 판매·결품·입고 소요 기간을 읽어 부족과 발주량을 추천한다. 근거 기간·가정·불확실성을 표시한다. 자동 발주하지 않는다. |
| 승인·실행·증거 로그 | L | 높음 | [추측] 사람 승인, 변경안 식별값, 대상 버전, 중복 방지 키, 실행 결과를 묶는다. 잘못된 승인이나 재시도가 실제 주문으로 이어질 수 있다. |
| 에이전트용 도구 | M | 높음 | [추측] 허가된 조회와 화면 메모리 제안만 제공한다. 관리자 전체 키·임의 SQL·셸·임의 외부 URL 도구는 제공하지 않는다. |
| The_IM 연결 | M | 높음 | [추측] 외부 연결이 허용되면 사람 결정과 우리 제안 ID를 대조한다. 원본 상태표를 복사한 라이브러리는 만들지 않는다. |
| 판매·주문 수정·반품 연결 | M | 높음 | [추측] 기존 Medusa 흐름 앞에 승인 검사를 둔다. 반품 입고와 재판매 가능 재고를 구분한다. |
| 미래 회계 연결 계약 | S | 중간 | [추측] 업무 ID·버전·외부 참조·수신 결과의 문서만 정한다. 회계 기능과 실제 전송은 만들지 않는다. |

## 크기를 확정하기 전 조건

1. [추측] MIT 설치 구성과 전체 의존성 범위를 먼저 검증한다. 검증하지 못하면 운영 구현으로 넘어가지 않는다.
2. [추측] 레거시 API와 비식별 표본을 확보한다. 조회 전용 계정 발급은 별도 사람 승인을 받는다.
3. [추측] 발주·가격·재고의 대표 사례와 실패 사례를 담당자가 선택한다.
4. [추측] 각 모듈의 원본 시스템과 승인자를 정한다.
5. [추측] 합성 데이터 검증 결과를 보고 범위와 크기를 다시 정한다.
